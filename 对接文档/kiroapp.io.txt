API 文档
用 API 令牌进行程序化调用，一个请求头搞定读写。

Base URL
http://kiroapp.io
鉴权
Authorization: Bearer km_…
到 设置 → API 令牌 生成令牌（明文只显示一次），之后每个请求带上上面的请求头即可——无需 Cookie、无需 CSRF，读写一致。令牌只能调 /api/me/* 前台接口。

curl http://kiroapp.io/api/me/stock \
  -H "Authorization: Bearer km_xxxxxxxx"
分页信封
列表接口统一返回 {items, total, page, page_size, pages}，参数 ?page=1&page_size=50（上限 500）。
错误格式
非 2xx 一律返回 {"error": "人类可读的原因"}。401 = 令牌无效/过期，403 = 无权限，429 = 触发限速。
安全边界
令牌泄露到设置页吊销即可；管理端接口不接受令牌，必须浏览器会话登录。

GET
/api/me/stock
库存与报价
可提取数量、在售价格区间与我的余额，下单前先查它。单价按母号累计产量分档，price 是最低价。

响应示例 · 200
{
  "stock": 120,
  "price": 30,        // = price_min，向后兼容字段
  "price_min": 30,
  "price_max": 65,
  "balance": 2060
}
POST
/api/me/purchase
下单购买（幂等）
扣积分并返回密钥明文。单价按【产出该 key 的母号累计产量】分档，同一单里各 key 可能不同价，便宜的先出货。幂等靠 client_order_id：相同 id 重放返回字节一致的原响应，绝不重复扣款。

Body 参数（JSON）
参数	类型	必填	说明
count	int	必填	购买数量
client_order_id	string	必填	32 位十六进制，调用方生成并保存，用于幂等重试
order_id	string	可选	可选：Webhook 推送里的开号批次 id，只拉取该批次产出的 key
请求示例
curl -X POST http://kiroapp.io/api/me/purchase \
  -H "Authorization: Bearer km_xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"count":5,"client_order_id":"a1b2c3d4e5f60718293a4b5c6d7e8f90"}'
响应示例 · 200
{
  "purchased": 5,
  "requested": 5,
  "remaining": 115,
  "unit_price": 38,      // 本单实际均价 = total_debit / purchased
  "total_debit": 190,    // 实际扣费总额，权威数字
  "order_id": "0d9f…",
  "keys": [
    {
      "key": "sk-…",
      "account": "user-…",
      "password": "…",
      "issuer_url": "https://…",
      "price": 30        // 这一个 key 实际扣了多少
    }
  ],
  "replayed": false
}
•
同 client_order_id 换 count 重放返回 409。
•
余额不足时按买得起的数量成交（purchased < requested）；有货但一个都买不起返回 403。
•
阶梯定价下前端无法精确预估总价，以 total_debit 与每个 key 的 price 为准。
•
网络超时后用同一个 client_order_id 重试即可，安全。

Body 参数（JSON）
参数	类型	必填	说明

gen_mode	string	可选	开号模式：group | user
响应示例 · 200
{ "id": "…", "generating": 0 }

事件推送
WEBHOOK
批次开号完成后向你配置的地址推送
POST <your_webhook_url>
Content-Type: application/json

// event: new_keys_available | all_keys_dead | key_revoked_abuse | test
{
  "event": "new_keys_available",
  "event_id": "<去重用的唯一 id，每次推送不同>",
  "order_id": "<开号批次 id>",
  "client_order_id": "d5c4fd9460b70fb8e944bd7faa519896",
  "mother_id": "<母号 id>",
  "visibility": "public",
  "message": "母号新开号完成，20 个 Key 就绪",
  "new_keys": 20
}

// 收到后直接下单：两个 id 原样带上，不必自己生成幂等键
POST /api/me/purchase
{ "count": 20, "order_id": "<order_id>", "client_order_id": "<client_order_id>" }
•
载荷不含密钥明文。收到后把 order_id 传给 POST /api/me/purchase 即可只拉取该批次的 key。
•
client_order_id 是替你备好的幂等键，无需自己生成。它由（批次 + 收件人）确定性派生，推送重试、重复推送、服务重启后都是同一个值——拉取超时后原样重发即命中幂等重放，不会二次扣费。
•
用 event_id 去重：推送失败会重试，同一事件可能送达多次。
•
回调地址在 设置 → Webhook 配置，可先发一条 test 事件验证连通。
